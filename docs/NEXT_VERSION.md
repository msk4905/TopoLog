# v0.3.0-dev.1 사용과 확인

## 프로젝트 선택·재수집

기존 창을 닫고 TopoLog-Batch.cmd를 다시 실행한다. 프로젝트 선택에서 실행할 프로젝트를 고른 뒤 일괄 수집을 누른다. 재수집 대상에서 과거 결과 폴더를 선택하면 실패·보류·미완료 또는 실제 사진 실패 프로젝트를 미리 선택한다. 선택 적용 후 일괄 수집을 누르면 된다. 의도적으로 사진을 끈 실행은 사진 때문에 재선택하지 않는다.

장비 한 대의 실패도 프로젝트 단위로 재수집한다. 네트워크 의존 장비를 함께 준비하기 위한 범위이며 장비별 시점이 다른 자료를 합쳐 성공으로 만들지 않는다. 매번 새 결과 폴더에 수집하고 원본은 유지한다. 자동 무한 재시도는 없고 한 번 누르면 한 번만 실행한다. summary.selection에 범위와 이전 결과 경로를 기록한다.

CLI: --project <프로젝트 UUID>를 반복하거나 --retry-from <기존 결과 폴더>를 사용한다. 두 옵션은 동시에 사용하지 않는다. 입력 폴더에 없는 선택은 서버 접속 전에 오류로 안내한다.

## 보고서와 공개 검토용 사본

보고서 다시 만들기는 기존 결과 폴더를 골라 장비 실행 없이 HTML·Word·manifest·ZIP을 갱신하는 기존 기능을 화면에 연결한 것이다. 결과 원문과 summary는 유지한다.

공개 검토용 사본은 선택한 결과에서 새 폴더로 HTML·Markdown·Word·이미지·필요 원문을 내보낸다. 알려진 암호·키·SNMP community 줄, PEM private key, 비밀 이름의 JSON 필드를 가린다. 인증/세션 바이너리 로그와 원본 프로젝트 파일을 복사하지 않는다. 원본 summary 해시와 편집 자료임을 기록한다. 자동으로 공개하거나 완전한 익명화를 보장하는 기능이 아니다. 이미지·주소·장비 이름·사용자 정의 비밀 값은 직접 검토해야 한다. 원본은 변경하지 않는다.

HTML·Markdown·Word의 실패/보류 검토는 동일 findings 자료를 사용한다. 원문 불일치를 설정 문제로 단정하거나 보류를 통과로 변경하지 않는다. Word 생성 실패는 report-document-error.txt에 보존한다.

## 실제 저장 결과 분석

dev.20의 세 프로젝트 사진은 captured, 2차 ping은 오류 없이 수행된 기록이 있다. IOS/ASA 페이지 설정 및 ASA 권한은 restored, Word 파일은 존재한다. F2 show route 원문은 연결/로컬 경로만 포함한다. 따라서 원격 경로 없음 6건은 원문에 없는 경로를 파서가 놓친 사례가 아니다. 수집 시점의 미수렴, 실제 광고/필터 구성, 자동 기대값의 범위를 추가 대조해야 하며 원인을 아직 확정하지 않았다. 이 개발에서 사용자 설정과 기존 결과를 고치지 않았다.

새 선택 수집·화면 동작·공개 사본의 실제 사용자 확인은 새 실행으로 확인한다. 공개 v0.2.0과 release는 보존했다. EXE·새 공개 데모는 이번 범위가 아니다.


## dev.2 추가 변경

서버 준비 기본 제한은 새 GNS3 실행 시 90초, 이미 실행 중이면 VM과 같은 60초로 적용한다. 응답하면 남은 시간과 무관하게 진행하며 기존 실행의 최초 응답 확인은 5초로 짧게 유지한다. 보고서의 자동 판정/자동 도출 표현, 지원 분야, 주소와 공개 주의 문단은 제거했다. 원문 보존과 비밀 값 가리기 자체는 유지한다.

20261006-1 F2의 show route는 2026-11-04 18:06:24 KST, 이웃 표는 18:06:25 KST이다. 그때 원격 경로는 없고 이웃은 FULL이다. 18:06:34 R1 경로 표에는 F2를 next hop으로 하는 원격 OSPF 경로가 있고 일부 경로 age는 4초다. 초기 경로 표를 네트워크 수렴 이후까지 그대로 사용한 수집 시점 문제가 유력하다. 당시 F2의 나중 경로 표가 없어 영구 구성 문제를 완전히 배제할 수는 없다. 다음 수집에서는 전체 장비와 ping 이후 F2 경로/이웃을 한 번 더 읽고 phase=final_routing 증거로 판단한다. 수렴을 가정해 실패를 통과로 바꾸지 않는다.


# v0.3.0-dev.3 — 2026-11-05

첫 ping의 응답률이 조건에 못 미치거나 해석할 수 없으면 해당 장비의 첫 대상 확인을 마친 뒤 5초를 기다리고 부족한 대상만 한 번 더 확인한다. 처음부터 충족한 대상은 반복하지 않는다. 최대 2회이며 대상별 5개 패킷 설정은 유지한다. 대기 중 중지 가능. 정책이 있는 무응답은 재확인 후에도 보류한다. 명령 거부는 반복하지 않고 증거 부족으로 남긴다.

각 시도의 원문·시각·파일·attempt를 보존하고 마지막 시도로 비교한다. 재시도 명령 자체가 실패/취소되면 이전 결과로 대체하지 않고 판정 불가로 남긴다. ping 후 crypto 상태를 읽는 순서와 전체 수집 후 ASA 경로 확인은 유지한다.



# v0.3.0-dev.4 — 2026-11-05

- IOS/ASA 모두 전체 수집 후 최종 경로·수집했던 관련 이웃 표를 재조회한다. IPv6 경로도 기존 수집 대상이면 갱신한다. 최초 원문과 새 phase/시각을 유지하고 명시 기준과 도출 기준 모두 최신 증거를 사용한다. 최신 명령 실패 시 옛 성공으로 대체하지 않는다.
- ASA 반대편 인터페이스를 ping 대상으로 사용하지 않는다. 직접 연결된 진입 인터페이스 주소만 선택하고 멀리 떨어진 ASA 주소는 생략한다. 다른 라우터 주소는 유지한다.
- 단일 토폴로지 경로의 ASA 보안 수준·활성 ICMP 검사·허용 ACL 유무에서 정책 제한 가능 사유를 제공한다. 커스텀 ACL/NAT/VPN·복수 경로 등 해석이 불확실하면 정책 검토로 남긴다. 설정 근거는 실제 drop/packet-tracer 증거와 구분하며 무응답을 통과로 바꾸지 않는다. 직접 연결된 ASA 인터페이스와 방화벽을 통과하는 ping을 구분한다.
- Word/Markdown 문서 이름에 수집 날짜(KST)를 추가: report(2026-11-05).docx, report(2026-11-05).md, report-document(2026-11-05).md. 재검토해도 원래 수집 날짜를 유지한다. 날짜 정보가 없는 옛 결과는 기존 이름을 지원한다.
- 결과 폴더와 ZIP 이름을 TopoLog_수집결과_2026-11-05_09-50-01 형태로 정리한다. 같은 초에 이름이 겹치면 _02 등 순번을 붙이며 기존 결과를 덮지 않는다. 재검토/공개검토는 이름으로 구분하고 옛 batch_ 결과도 계속 찾는다.
- 문서·링크·AI 프롬프트의 파일 참조를 새 이름과 연결하고 콘솔 출력 캡션의 '화면 캡처 아님' 문구를 삭제한다.

전체 재수집 전에 20261006-1만 선택해 새 수집한다. 모든 IOS/ASA에 final_routing 기록이 있는지, R1의 경로 없음이 최종 표에서도 유지되는지, ASA ping 목적지가 진입 주소인지 확인한다. 기존 결과의 재검토는 새 장비 출력을 추가하지 않으므로 과거 시점의 미확인은 유지한다.
