# enable 권한과 저장 설정 수집

## 권한 전환

IOS/ASA의 `>` 프롬프트를 발견하면 다음 순서로 enable을 시도합니다. 이미 `#`이면 권한을 변경하지 않습니다. 로그인 사용자명·로그인 암호의 자동 입력과는 별도 기능입니다.

1. GUI의 **기본 enable 암호(선택)** 또는 CLI 환경 변수로 지정한 기본 암호
2. 암호 없음(빈 암호)
3. 이번 실행에서 다른 장비에 입력해 성공한 암호(메모리에만 보관)
4. 위가 모두 실패하면 해당 장비에서 가려진 입력 창으로 사용자에게 한 번 묻습니다.

같은 암호를 두 번 보내지 않습니다. 장비가 남은 암호 입력 기회를 요구하면 빈 입력으로 넘겨 원래 프롬프트로 돌아갑니다. 시도 후 콘솔 상태를 확인할 수 없으면 추가 암호를 보내지 않고 이유를 기록합니다. ASA처럼 장비가 **새 enable 암호 설정**(Enter/Repeat Password)을 요구하면 설정 변경이 되므로 입력하지 않고 권한 부족으로 남깁니다.

GUI의 **필요 시 enable 권한 전환**을 해제하면 권한이 부족한 노드를 requires_privilege로 남깁니다. 입력 창을 취소하면 해당 장비를 권한 부족으로 남기고 다음 장비로 진행합니다.

기본 암호 입력란과 입력 창은 모두 값을 가립니다. 입력 창이 뜰 때 TopoLog 창을 다른 프로그램 위로 올리고 알림음을 내며, 입력이 끝나면 맨 위 고정을 해제합니다. collection.json에는 시도 출처(default/none/earlier_input/user_input)와 결과만 남습니다. 설정 파일·기준 파일·보고서에 암호를 저장하지 않습니다. 인증 단계의 수신 바이트도 증거에서 제외하며, 해당 생략을 collection.json에 명시합니다. 장비 running/startup 설정 원문은 별도의 수집 자료입니다.

수집 후 원래 `>` 권한으로 복원을 시도합니다. 중지·오류·암호 대기 중단에도 가능한 프롬프트 복원을 시도하며, 복구할 수 없는 경우 이유를 남깁니다. 처음부터 `#`였던 장비를 임의로 `>`로 내리지 않습니다. 저장 구성 변경 명령은 실행하지 않습니다.

CLI도 대화형 실행에서는 필요할 때만 숨김 입력을 요청합니다. 무인 실행에는 입력을 요청하지 않습니다. 선택적으로 사용하는 기본 암호 환경 변수는 `TOPOLOG_ENABLE_PASSWORD`입니다. 변수 이름은 `--enable-password-env`로 지정할 수 있고, `--no-enable`로 권한 전환을 끕니다. 암호 자체를 명령 인수에 넣는 옵션은 없습니다.

## 저장 설정

IOS 계열은 먼저 기존 GNS3 API 저장 파일을 조회합니다. 사용할 수 없거나 ASA처럼 해당 파일 경로를 모르면 `show startup-config`를 추가로 읽습니다. 유효한 설정 출력이 있을 때만 startup.cfg로 저장하며 실행 설정을 저장 설정으로 복사하지 않습니다.

보고서와 collection.json에 수집 여부 및 `api`/`console` 출처를 표시합니다. API 실패·설정 부재·권한 부족은 미수집 상태로 보존합니다. API와 콘솔의 같은 출력 형식이 모든 장비·버전에서 지원된다고 보장하지 않습니다.

## 현재 검증 범위

기본 암호→암호 없음→이전 입력→입력 창 순서, 새 암호 설정 요구 미응답, 상태 불확실 시 중단, 잘못된 암호 비재전송, 취소 후 복원, 인증 바이트 제외, ASA 수집, startup CLI 대체와 설정 부재 처리를 합성 콘솔로 검사했습니다(dev.19 자동 검사 140개, Linux 대체 실행). 실제 ASA·IOS 장비에서 새 순서의 입력 창 표시는 아직 확인하지 않았습니다.

dev.13의 도구 직접 ASA 검증은 VM 콘솔 TCP 접근 거부로 완료하지 못했습니다. 이후 dev.14에서 로그인 이력 오탐을 수정했고 사용자가 동작 확인을 알려 주었습니다. 이번 암호 입력 변경과 일괄 자체 사진 흐름은 사용자 환경의 새 실기 확인이 남아 있습니다. NAT·ACL 전체 정책의 자동 의도 판정은 지원 범위가 아닙니다.
