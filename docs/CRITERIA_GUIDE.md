# 자동 분석과 선택적 기대값 편집

## 기본 자동 분석（v0.2.0-dev.7）

수동 기준 파일 없이 실행하면 설정과 프로젝트 연결에서 기능과 검증 조건을 자동 도출합니다. 기능은 여러 개를 조합하며 프로젝트명으로 실습 종류를 고정하지 않습니다. 기대값 편집과 수동 파일은 선택적인 재정의 기능입니다.

| 범위 | 자동 처리 |
| --- | --- |
| 인터페이스 | 설정된 활성 인터페이스의 IPv4 주소와 운영 출력 비교 |
| OSPF | 실제 연결·동일 서브넷/area·명시적 router-id로 기대 이웃 도출. passive·중복 ID·다중 접속망의 FULL 단정은 제외 |
| RIP | 단순한 RIPv2/no auto-summary 도메인에서 상대가 광고하는 원격 prefix 기대값 도출. 혼합 프로토콜·정적 경로·요약 모호성은 보수적으로 처리 |
| VLAN·Trunk·HSRP | 설정된 VLAN 활성, 명시적 trunk 운영 상태, HSRP 그룹/가상 IP와 참여 상태 확인 |
| STP·DHCP·IOS 정적 NAT·IOS ACL | VLAN의 STP 인스턴스·풀 주소 범위·단순 정적 주소 변환·인터페이스 ACL 적용을 설정과 비교. 종단 통신·전체 정책은 별도 |
| VPN·재분배·정적 경로·EIGRP·BGP·IPv6 | 가능한 show 출력 수집. 자동 확정하지 못한 전체 기능·정책 의도는 미검증 |
| 기타 기능 | 분류하지 못한 설정 종류를 표시하고 running-config 원문 보존. 자료에서 누락하거나 정상으로 추정하지 않음 |

추가 명령이 장비 버전에서 지원되지 않으면 해당 증거 부족을 기록합니다. 설정만으로 DHCP 할당 성공·ACL 허용/차단 의도·VPN 종단 통신을 확정하지 않습니다. 자동 passed는 생성한 조건의 충족이며 전체 설계 의도나 모든 기능의 정상 보증이 아닙니다.

**기존 결과 다시 판정**도 기준 파일 없이 자동 분석할 수 있습니다. 과거에 수집하지 않은 추가 명령은 재실행하지 않고 증거 부족으로 남기므로, 새 기능의 운영 증거까지 필요하면 새로 수집합니다. `auto-criteria.json`에 자동 조건·근거·판정을 기록합니다. 수동 편집용 기준 파일과는 별도 형식입니다.

검증: 자동 검사 79개 통과. 실제 OSPF 프로젝트를 수동 기준 없이 새로 수집해 4대의 자동 조건 16개가 모두 passed, 정리 오류 0건이었습니다. VLAN·Trunk·HSRP 및 RIP 자동 도출은 합성 출력/설정 검사이며 해당 장비의 새로운 실기 성공을 주장하지 않습니다.

# 기대값 편집과 동작 판정

수집 성공은 명령 출력을 확보했다는 뜻입니다. 동작 판정은 사용자가 지정한 기대값과 그 출력을 비교합니다. 수동 기대값이 없으면 자동 분석하며 도출할 근거가 부족하면 미검증으로 남습니다.

## 화면에서 기준 만들기

1. 프로젝트 폴더와 결과 저장 폴더를 선택하고 **기대값 편집**을 누릅니다.
2. 프로젝트를 펼쳐 장비 이름을 선택합니다. 플랫폼은 기본 `auto`를 권장합니다. OSPF·RIP·재분배 등 필요한 수집 프로필을 선택합니다.
3. 기준 종류와 기대값을 입력하고 **추가**를 누릅니다. 기존 기준을 선택하면 입력란에서 편집한 뒤 **선택 기준 수정**으로 반영할 수 있습니다. **기준 파일 저장**으로 JSON을 저장합니다.

프로젝트와 노드 ID는 자동 연결되므로 직접 입력하지 않아도 됩니다. 여러 장비의 기준을 한 파일에 저장할 수 있습니다. 파일을 다시 선택하고 편집하면 기존 기준을 유지합니다. 이름이 달라도 UUID가 다르면 다른 장비로 취급합니다. 파일에만 남은 대상은 결과의 기준 대상 불일치로 확인할 수 있습니다.

| 기준 | 입력 | 의미 |
| --- | --- | --- |
| OSPF 이웃 | 기대 Router ID 목록 | 지정한 각 이웃의 FULL 상태 확인 |
| 경로 | CIDR prefix, 경로 코드, 선택 next hop | 기대 경로가 해당 프로토콜로 학습됐는지 확인 |
| Ping | 목적지 IPv4, 최소 성공률 | 수집 시 명시한 대상에 Ping을 수행하고 성공률 비교 |
| 출력 문구 | 지원 show 명령, 한 줄당 기대 문구 | 명령 echo·프롬프트를 제외한 본문에 모든 문구가 있는지 확인 |

RIP 경로 코드는 `R`, OSPF는 `O`, 외부 재분배 경로는 실습에 따라 `O E1`, `O E2` 등을 사용합니다. next hop은 특정 경로를 요구하는 경우에 입력합니다. 경로 선택이 달라도 허용하는 실습이라면 비워 둡니다. 이전 실행의 관측값을 그대로 정상 기준으로 확정하지 말고 실습 의도에 따라 지정하세요.

구형 IOS의 `is subnetted` 표에서 생략한 prefix 길이와 CIDR 표기를 처리합니다. prefix 길이를 증거로 확정할 수 없으면 판정 불가로 남깁니다. 모든 장비 출력 형식이 지원되는 것은 아닙니다.

ASA packet-tracer 등 기존 JSON 기준은 엔진에서 계속 사용할 수 있습니다. 이번 화면에서 편집을 제공하는 종류는 위 네 가지이며, 그 외 기존 기준은 저장 시 보존됩니다. ASA enable 전환과 원래 권한 복원을 지원합니다. 기본 시도는 암호 없이 수행하며 필요한 장비에서만 가려진 입력을 요청하고 저장하지 않습니다. 상세 내용은 PRIVILEGE_AND_STARTUP.md를 확인하세요.

## 새로 수집하며 판정

GNS3와 연동 VM을 준비한 뒤 기준 파일이 선택된 상태에서 **일괄 수집**을 누릅니다. 프로젝트나 노드는 미리 켤 필요 없습니다. 원래 실행 상태를 기록하고 TopoLog가 시작한 대상을 정리합니다.

**중지**는 현재 작업을 중단하고 가능한 상태 복구 및 결과 저장을 수행합니다. 창을 닫아도 복구가 끝날 때까지 기다린 뒤 종료합니다. 입력과 기준 편집은 수집 중 잠깁니다. 네트워크 요청은 응답 또는 타임아웃까지 기다릴 수 있습니다.

IOS 터미널 길이는 정상·명령 오류·중지 시 복원을 시도합니다. 명령 응답 중단 상태에서는 먼저 Ctrl+C로 프롬프트 동기화를 시도한 뒤 복원합니다. 연결 단절 등으로 복원하지 못하면 복구 오류를 기록하며 성공으로 숨기지 않습니다. 이 처리는 영구 장비 설정을 저장하지 않습니다.

## 기존 결과 다시 판정

기준 파일은 선택 사항입니다. **기존 결과 다시 판정**에서 `summary.json`이 있는 기존 결과 폴더를 선택합니다. 장비에 접속하거나 명령을 다시 실행하지 않습니다.

- 원본 결과를 유지하고 새 결과 폴더와 ZIP을 생성합니다.
- 원래 수집 시각과 별도로 재판정 시각·원본 경로·summary 해시를 기록합니다.
- 수집 당시 실행하지 않은 Ping 등은 증거 부족으로 판정 불가입니다. 명령을 실제로 추가 실행하려면 새로 수집해야 합니다.
- 결과에는 기대값·관측값·근거 파일·미완료 이유가 함께 표시됩니다.
- 재판정은 파일 복사와 평가 작업이 끝난 뒤 결과를 보여주며 별도 중지 기능은 제공하지 않습니다.

CLI에서도 사용할 수 있습니다.

```powershell
.\TopoLog-Batch.cmd --reassess "기존 결과 폴더" --rules "criteria.json" --output-dir "새 결과를 저장할 폴더"
```

`passed`는 지정한 기준의 충족을 의미합니다. `failed`는 기대값과 관측값 불일치이며, `inconclusive`는 미검증·증거 부족·미지원·복구 실패 등이 남은 상태입니다. 일부 장비만 기준을 지정하면 다른 장비의 미검증 때문에 전체는 inconclusive일 수 있습니다.
